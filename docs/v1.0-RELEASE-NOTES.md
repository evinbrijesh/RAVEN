## 🚀 Executive Summary: The Closed-Loop AI Security Platform

We are thrilled to announce the official **v1.0.0 production release of RAVEN** — the autonomous security regression and remediation assurance platform for LLM applications and agent backends.

Traditional AI red-teaming scanners are **open-loop**: they generate static vulnerability lists, leaving developers to guess what to patch and wondering if their prompt changes broke legitimate customer workflows.

**RAVEN is closed-loop**:
1. **Discovers** vulnerabilities with cryptographic-grade evidence (exact canaries, PII leaks, unauthorized tool calls, MCP exploits).
2. **Synthesizes** constrained mitigations (system prompt diffs + deterministic `raven-policy.yaml` runtime guardrails).
3. **Guards** with human-in-the-loop approvals backed by atomic concurrency guards (`HTTP 409 Conflict`).
4. **Measures the Frontier**: Re-tests attack cases alongside a **benign utility suite** to quantify security gains vs. over-refusal penalties.
5. **Findings Become Tests**: Converts confirmed findings into continuous regression suites executed on every CI commit and PR via GitHub Actions.
6. **Enforces at Runtime**: Automatically compiles guardrails directly into [`raven-guard`](packages/raven-guard) for fail-closed runtime defense.

### 1. `raven-test` Standalone Developer CLI
Available on PyPI via `pip install raven-test`:
* **Interactive Initialization (`raven-test init`):** Scaffolds a starter `raven.yaml` configuration with local port auto-detection (detecting local agent endpoints on ports 8000, 3000, 8080).
* **Pre-Flight Validation (`raven-test run --dry-run`):** Tests target connectivity and profiles tool schemas with 0 attack requests.
* **Declarative CI Gate (`raven-test run --config raven.yaml --fail-on high`):** Runs regression scans, benchmarks before vs. after Attack Success Rate (ASR), and evaluates against severity thresholds.
* **Frontier Scorecard:** Colorized diff viewer (green additions, red removals) and clean ASCII/Rich terminal scorecard showing ASR reduction and 0.0% over-refusal.

### 2. Official GitHub Action (`actions/raven-security-scan`)
A 1-line pull request gate that blocks vulnerable code and posts reviewable remediation proposals:
```yaml
- name: Run RAVEN Security Scan
  uses: raven-security/raven-security-scan@v1
  with:
    config-file: "raven.yaml"
    fail-on: "high"
    github-token: ${{ secrets.GITHUB_TOKEN }}
    comment-on-pr: "true"
```
* **Automated PR Scorecard Comment:** Automatically posts or updates an interactive markdown dashboard on active PRs comparing pre-scan vs. post-patch metrics.
* **Benign Utility Retention:** Proves 0% over-refusal against legitimate customer queries before human approval.
* **GitHub Workflow Annotations:** Emits native `::error file=...` annotations pointing directly to vulnerable tool definitions or prompt files in the PR diff.
* **OASIS SARIF 2.1.0 Export:** Ingests findings directly into repository GitHub Code Scanning Alerts.

### 3. Model Context Protocol (MCP) Security Auditing
Direct evaluation of Model Context Protocol (MCP) servers and tool endpoints via HTTP/SSE and stdio:
* **Target Scanning:** `raven-test run --target mcp://localhost:8000/sse --categories tool_misuse`
* **MCP-Specific Threat Vectors:**
  * Tool description injection
  * Confused deputy privilege escalation
  * Schema parameter smuggling

### 4. `raven-guard` Runtime Policy Gateway SDK
A standalone, zero-heavy-dependency Python library (`pip install raven-guard`) providing runtime defense for tool-calling agents:
* **Fail-Closed Execution:** Denies unapproved or unrecognized tools by default.
* **Drop-In Function Decorators:** `@gateway.protect(tool="issue_refund")` for both synchronous and asynchronous Python tool functions.
* **Native Framework Middleware:**
  * **FastAPI Middleware:** `RavenGuardMiddleware` automatically extracts headers and claims into execution context.
  * **LangChain & LangGraph Integrations:** `RavenGuardToolNode`, `RavenToolInterceptor`, and `RavenGuardCallbackHandler`.
* **Dynamic Condition Checking:** Validates financial bounds (`amount <= 100.0`), verified order ID presence, user ownership matching, and rate limits.
* **Structured Security Observability:** Emits OpenTelemetry-compatible security trace events with audit logs for every policy violation and approval escalation.

### 5. Runnable Starter Demo Agent (`examples/vulnerable-agent/`)
A complete reference template featuring:
* A FastAPI agent exposing an unconstrained `issue_refund` tool.
* Preconfigured `raven.yaml` with local dev support.
* Ready-to-run GitHub Actions workflow (`.github/workflows/security-gate.yml`) demonstrating automated PR blocking and remediation diff generation.

### 6. Security Self-Audit & Zero-CVE Guarantee
* **Non-Root Container Execution:** Verified non-root user `USER raven` execution across all Dockerfiles (`Dockerfile.api`, `Dockerfile.worker`, `Dockerfile.backend`, and `Dockerfile.web`).
* **Zero CVE Audit:** Passed `uvx pip-audit` and `npm audit` with **0 known vulnerabilities** (0 High/Critical CVEs).

## ⚡ Quickstart Guide

### 1. Install CLI
```bash
pip install raven-test
```

### 2. Initialize Project
```bash
raven-test init
```

### 3. Run Pre-Flight Dry Run
```bash
raven-test run --dry-run
```

### 4. Run CI/CD Scan
```bash
raven-test run --config raven.yaml --fail-on high
```

### 5. Protect Tools at Runtime with `raven-guard`
```bash
pip install raven-guard
```

```python
from raven_guard import PolicyGateway, security_context

gateway = PolicyGateway("raven-policy.yaml")

@gateway.protect(tool="issue_refund")
def process_refund(order_id: str, amount: float):
    return {"status": "success", "order_id": order_id, "amount": amount}

# Normal execution protected by policy bounds:
with security_context(verified_user=True, verified_order_id=True):
    result = process_refund(order_id="ORD-101", amount=45.0)
```
